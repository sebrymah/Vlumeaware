Most of the features below live in the code but are not on the live site yet. Nothing in suites B–G will pass until this is done.

1

Push the code. From the repo, commit and push to main. Vercel redeploys the web app automatically; Render rebuilds the API. Wait for both to go green.

2

Add the Supabase Storage env vars on Render (API service → Environment), then let it redeploy: SUPABASE_URL=https://dsytyibazgoflkjgozsb.supabase.co, SUPABASE_STORAGE_BUCKET=training-videos, SUPABASE_SERVICE_ROLE_KEY=<service_role secret from Supabase → Settings → API>. Without these, uploaded videos still won't play.

3

Delete the old “Test awareness” video and re-upload it. The existing one points at a wiped file:// path and will never play. Only uploads made after step 2 get a real playable URL.

4

Decide how emails send. By default the API uses the log mailer — it records sends but delivers nothing. Real delivery needs MAILER=ses plus AWS SES (verified domain). To test the click/quiz flow without email, use the token method in the callout below.

Rotate the exposed database password and change the seeded demo passwords before any real client data goes in.

Testing the simulation without a real inbox

With the log mailer, no email is delivered — but every send still gets a unique tracking token. To walk the employee journey: launch a campaign, then read the token from the sends table (or ask me to fetch it), and open https://vlumeaware.onrender.com/track/click/<token> in a private window. That records the click and drops you on the simulated landing page → teachable moment → training video → quiz, exactly as an employee would see it.
